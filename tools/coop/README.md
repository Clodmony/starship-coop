# Co-op tools

Python 3 scripts, so they work the same on Windows (PowerShell), Linux and macOS. Python is already needed to build
Starship. Run them from the repository root.

| Script | What it does |
|---|---|
| `python tools/coop/build.py` | Configure, build and run the checks; prints `build: OK` or `build: FAILED at <step>`. `--quiet` for a summary only, `--config Release`, `--assets` (needs `baserom.z64`), `--clean`. `--build-dir <folder>` holds a second config beside the first, as nothing is shared between build folders (#147); one folder holds one config, and it says so if asked for another. CI runs the same script. |
| `python tools/coop/net_test.py` | Transport tests: a virtual network, then two real processes through the chaos relay. `--only a,b`, `--list`, `--no-build`, `--asan` (the same under AddressSanitizer and UBSan, not on Windows). Needs a configured build directory, no ROM. Logs in `local/test-net/`. |
| `python tools/coop/session_test.py` | Session tests: the handshake (WP-21) with build, ROM, CVar and platform mismatches, and characters (WP-34) with three clients, in a virtual network, then real processes over UDP and the chaos relay. `--only a,b`, `--list`, `--no-build`, `--asan` (the same under AddressSanitizer and UBSan, not on Windows; CI runs it on Linux). No ROM needed. Logs in `local/test-session/`. |
| `python tools/coop/replay.py record\|play <file>` | Records or plays back controller input (WP-03) in a fresh `local/test-replay-*` folder with its own `SHIP_HOME`. `record` stops when you close the window, or by itself with `--frames <n>`. `play` runs unattended and exits 0 on `PASS`: only a whole file can pass. `--hash-log` also writes the per-frame state hash, `--exe`, `--timeout`. A file only plays on the build and platform it was recorded on. A test game runs with no frame limit, makes no sound, on Linux opens no window (`game_env`, #137) and does not draw (#147): its draw code runs, and the renderer gets an empty display list. `--speed 1` gives real time, `--speed` also gives drawing, and a driver set in the shell still wins. `record` without `--frames` stays as a person needs it. `--start level` or `flying` starts a game straight in Corneria, before or past its intro (#148): the table in `docs/coop/QA.md` says which tool plays which. A replay with checkpoints plays from where it was made. |
| `python tools/coop/player_trace.py run <replay> --players 2` | Plays a replay with several co-op players in a fresh `local/test-trace-*` folder and checks the per-frame player trace (joins on rails and in all-range with player 0, stays on player 0's path, moves). `check <trace.txt>` checks an existing trace. `rails --players 2`: input by rule on Corneria's rails, with one player and with N at the same time, and compares path progress on every frame (WP-12). `shots --players 2`: input by rule in all-range, with shots carried to the wingmen: a shot of players 1 and up must not read as an enemy's hit, and a ground hit must follow the shooter's own lasers (#86). `lowhealth --players 2`: four games one after the other, with shields held low for one player or the other, and checks the low-health radio timer against single player on every frame (#87); `--section all-range` flies there instead. About 5 minutes. `effects --players 2`: places each enemy effect of #100 on each player in turn on Corneria's rails, or after the jump with `--all-range`, and checks who it hit (`SF64_COOP_EFFECT_PROBE`). Input by rule starts straight in Corneria (#148): `rails` before the intro, the others past it. Needs the replay code from WP-03 in the build. |
| `python tools/coop/hash_check.py run\|probe\|views\|builds\|rates\|start\|draw\|base\|diff` | State hash checks (WP-04, #53). `run [<replay>]`: two runs must match and a one-bit poke must show at exactly its frame; `--players 2 --poke-player 1` for co-op. `probe`: one game checks what the hash can and cannot see, player by player and per-player array by array (#67). Without a replay they play input by rule. See `docs/coop/QA.md`. `views`: one replay with local index 0 and 1 must hash alike on Corneria's rails and all-range (#96); the client with index 1 has also ticked 6 more frames since boot (`--skew`, #129). `--level katina,fortuna` or `all` flies other Arwing levels instead, `--cvar NAME=VALUE` sets a CVar on both, and the two clients render different audio sample counts (`--audio`). `slots --level katina,fortuna,corneria`: plays a level with 1 player and with 2 and fails when co-op holds more than 15 more effect slots (median), as nothing frees an effect for leaving the view in co-op (#129). `builds --debug <exe> --release <exe>`: two Release runs and a Debug run of one commit must hash alike (#141). `rates`: one replay at several `gInterpolationFPS` must hash alike, with vsync off, and each run must make the draws its rate asks for, counted at the draw loop (#141). Both run in real time and draw, as no game interpolates at test speed (#137), and each game must log its draws. `draw`: one replay with and without `SF64_COOP_TEST_NO_DRAW` must hash alike on Corneria's rails and all-range, from each start or the one `--start` names, with 0 draws in one and more in the other (#147). `base --base <exe>`: input by rule through the menus with co-op off must hash alike on this build and the one before a change. `start`: a game from the menus and two started in the level from its seeds must hash alike (#148). `run`, `probe` and `views` play straight in Corneria, `builds` and `rates` through the menus. |
| `python tools/coop/determinism.py [<replay>]` | Determinism check (WP-02): plays one replay alone as the baseline, then again several times at once under conditions that can differ between machines (graphics backend, window size, audio timing, FMA3), and each run's state hash must equal the baseline on every frame. Every run is in real time but the variants `speed`, no frame limit with drawing (#137), and `no-draw`, which runs as the other tools do (#147). A run that did not make the draws its variant asks for fails. Without a replay it plays input by rule, Corneria's rails into all-range. It keeps the whole path from boot and fails on a game that started in a level (#148). `--only a,b`, `--exe`, `--timeout`. |
| `python tools/coop/replay_test.py` | Tests the replay tools themselves (#54): records a short replay nobody plays, then plays it whole and damaged through `replay.py`, `hash_check.py` and `determinism.py`. Only the whole file may pass, and a decoy `SHIP_HOME` must stay untouched. Each tool's games must log the right speed, and on Linux a tool started from a shell without SDL drivers must give its game the silent ones, read from the running game's environment, and `hash_check.py rates` must hold at real time and fail at speed (#137). Every game must draw or not draw as its tool says, and the tools that need pixels must fail when they get none (`*-no-draw`, #147). A replay made in a level plays from there, and `determinism.py` and `full_level.py` refuse it (#148). `--only a,b`, `--list`, `--exe <file>`, `--jobs <n>` (scenarios at a time). About 2 minutes, more on a busy machine, needs a build with `--assets`. Logs in `local/test-replaytools-*`, kept when a scenario fails. |
| `python tools/coop/exit_test.py` | Tests that a test run ends soon after SIGTERM, SIGINT or SIGQUIT (#71) or a crash (#98): without a replay, recording and playing. Each game must end within 10 s, with exit code 0 after a stop signal and 1 after a crash, and the report, the replay and the hash log must keep their end; a crash must also leave its crash log. `crash-*` send a crash signal, `fault-*` use gdb for a real fault on the main or the audio thread and for a crash handler that hangs. `plain` and `crash-plain` show that a game with no test variable keeps upstream's handlers. Every game draws, and a run that logged no draws fails (#147). `--only a,b`, `--skip a,b`, `--repeat n` (default 3), `--exe`, `--list`. Linux only, about 7 s per game, needs a build with `--assets`, and gdb for `fault-*`. Logs in `local/test-*`, kept when a run fails. |
| `python tools/coop/net_mutants.py` | Mutation check for the transport: breaks one behaviour of `net_core.c` at a time, rebuilds, and requires the named `net_test.py` scenarios to fail. Prints caught or SURVIVED per break; exit 0 only when all are caught. `--only a,b`, `--skip a,b`, `--list`, `--check` (patterns only, no build), `--asan` (the breaks only the sanitizers can see, not on Windows). About 10 minutes. Run it after changing `net_core.c`, and add a break for every bug you fix there. |
| `python tools/coop/session_mutants.py` | The same for the session: breaks one behaviour of `session.c` at a time and requires the named `session_test.py` scenarios to fail. Same options as `net_mutants.py`. The top of the file lists the changes no test can see, with the reason. About three minutes. Run it after changing `session.c`, and add a break for every bug you fix there. Both tools run on `mutants.py`, which also holds the rules for how a run guards the source. |
| `python tools/coop/check.py` | Repository checks, also run by `build.py` and `test_all.py`: no ROMs, asset archives or Steamworks SDK files tracked, no file over 5 MB, skills mirrored, unique protocol ids, every break in `net_mutants.py` and `session_mutants.py` still matches, `script_reader_test.py` passes, every test tool gets a run folder of its own (`run_folder_test.py`), `test_all_test.py` passes, libultraship builds in the build folder, `sp_audit.py --check` and `sp_audit_test.py` pass. Runs inside `build.py`, so a stale audit fails a local build too. Prints `ALL OK`. |
| `python tools/coop/new_worktree.py <issue> <slug>` | Worktree plus branch `issue/<issue>-<slug>` from `origin/coop`, with submodules. |
| `python tools/coop/sp_audit.py` | Single-player assumptions audit (WP-05): every `gPlayer[0]`, `gPlayer->`, bare `gPlayer` argument, `gMainController` and `gCamCount` site, and every write and test of who fired (`dmgSource`, `sourceId`, #86), in the game code with its function and the verdict from `docs/coop/audit/sp-verdicts.tsv`; writes `docs/coop/audit/single-player.md`. `--check` compares the list with what a rerun would write, in everything but line numbers: it fails when a site is new, lost, has another verdict, basis or note, or has no verdict, or when any other text differs. A moved line passes until the next rerun refreshes its number. `--todo` lists functions without a verdict. A site the committed list does not have stops the rerun and stays red, named with the row it would take its verdict from, until `--accept` takes it in: read those sites, fix the rows that do not fit, then run that one command, also after an upstream sync. Anything but a new site needs only the plain rerun. A file git does not track gets a warning, and so does a tracked file that is deleted but not committed. `python tools/coop/sp_audit_test.py` tests the tool itself (`--only a,b`, `--list`): no build, no ROM, a few seconds, folders in `local/test-spaudit-*`, kept when a scenario fails. |
| `python tools/coop/script_reader.py CO S59:34` | Prints a level event script from your own `sf64.o2r` (#90), the command marked with `>`; `Corneria 17.8` is the same kind of reference. A level alone lists its scripts, no argument the levels. `--o2r <file>`, by default the first of `build-cmake/`, `build/x64/` and the repo root. It reads that one file and writes nothing; what it prints is game data, so keep it out of git, issues and PRs. `python tools/coop/script_reader_test.py` tests the tool on made-up scripts (`--only a,b`, `--list`): no build, no ROM, a few seconds, `check.py` runs it, folders in `local/test-scriptreader-*`, kept when a scenario fails. |
| `python tools/coop/run_folder_test.py` | Tests that a test tool's run gets a folder of its own, however close together runs start (#104): `replay.py`, `player_trace.py`, `exit_test.py`, `test_all.py`, `net_test.py`, `session_test.py` and `mutants.py` as real processes with the clock stopped, and `make_run_folder` in `run_folder.py`, which they all share, across processes and threads. `--out` must stay a folder runs can share. `--only a,b`, `--list`. No build, no ROM, a few seconds; `check.py` runs it. Folders in `local/test-runfolder-*`, kept when a scenario fails. |
| `python tools/coop/join_test.py` | Real game clients through the join flow (WP-24): host and clients over loopback, nobody at the keyboard, each with its own replay and seeds, at a frame limit, as a join takes wall-clock time (#147). Compares the state hash logs frame by frame from the level start, and the seeds, team values and characters each game ended up with. Keeps the whole path from boot and fails on a game that started in a level (#148). `--only a,b`, `--list`, `--frames <n>`. Needs a build with assets; folders in `local/test-join-*` and `local/test-replay-*`. The scripted flow in the game is `src/port/coop/test/join_driver.h`. |
| `python tools/coop/menu_test.py` | Co-op menu tests (WP-25): `sim` runs the menu layer on the real session in a virtual network and checks what can be chosen, status and ping, `udp` does a shorter run over real sockets. `--game` also starts real games with no window, at a frame limit as in `join_test.py`, and clicks the real ImGui widgets: `game` for host, join, a taken character, ping, a refusal, `game_level` for the Start button into a level, with the state hash logs compared as in `join_test.py`, `game_start_level` for the host's dropdown of the level to start at (#211), `game_level_map` the same for a host that came from the map, `game_platform` for what the menu shows both sides for a platform warning, against `coop_session_test` as the other side. `--only a,b`, `--list`, `--no-build`, `--exe`, `--asan` (`sim` and `udp` under AddressSanitizer and UBSan, not on Windows), `--keep`. `sim` and `udp` need no ROM, `--game` needs a build with assets. Logs in `local/test-menu/`. |
| `python tools/coop/package.py --config Release` | Puts a built game into `<build dir>/package/starship-coop-<id>-<os>-x64/` to hand a test build to another player (#26). `<id>` comes from `coop/coop_build_id.h` in the build folder. Only listed files go in, plus `starship.o2r`, which it packs itself from the 13 tracked `port/` files, with no Torch build. The result is scanned for ROMs and asset archives by name, by first bytes and for a ROM header inside a file; `starship.o2r` must equal, byte for byte, what the tracked files give. `--out <folder>`, and `--scan <folder>` only scans, for example a downloaded artifact. `python tools/coop/package_test.py` tests it: no build, no ROM, a few seconds, run it after changing `package.py`. |
| `python tools/coop/math_test.py` | Tests the sine and cosine that a session uses instead of the C library (#186, decision 0011). Compiles `src/port/coop/math/sincos.c` alone with the platform's own compiler and compares it, bit for bit, with a Python port of the N64 algorithm on about 11000 inputs: every half degree the game feeds `SIN_DEG` and `COS_DEG`, random floats and the edges of each branch. It prints how many inputs this platform's own `sinf` and `cosf` round differently. Needs a C compiler; no build, no ROM, a few seconds; folder `local/test-math/`, kept when it fails. Run it on Windows too: the expected values need no table, so the same run on both platforms is the proof. |
| `python tools/coop/rand_order.py` | Lists the statements of the game that take two random draws where C leaves their order to the compiler (#199): two draws as operands of one expression (`operator`, the class of the Macbeth desync), in two arguments of one call (`args`), in one brace initializer (`init`). `--check` (in `check.py`) fails when a file has more or fewer of them than its list `KNOWN`, which `docs/coop/NOTES.md` (2026-11-09, #199) explains; a statement that calls a `CoopRand_` function counts as handled. Source only, no build. |
| `python tools/coop/rand_order_test.py` | Tests the above (#199): the scanner on made-up statements and its list check (`--no-compiler`, in `check.py`), and `src/port/coop/math/rand_order.c` compiled alone with the platform's own compiler against a Python reference that draws left to right, bit for bit. Prints, for information, which order this compiler takes `RAND_FLOAT(1.0f) - RAND_FLOAT(2.0f)` in when compiled alone. Needs a C compiler; no build, no ROM, a second; folder `local/test-rand-order/`, kept when it fails. Run it on Windows too. |
| `python tools/coop/handover_test.py` | Tests the rules of the handover at the end of a session (#189), `src/port/coop/sync/handover.c` compiled alone with the platform's own compiler, under AddressSanitizer and UBSan where it has them: the names a received report may have (`..`, a path separator, an absolute path, the receiver's own player number and another prefix fail) and the size caps (size 0, above 2 MiB, a fifth file, more than 4 MiB from all peers). Needs a C compiler; no build, no ROM, a few seconds; folder `local/test-handover/`, kept when it fails. The transfer between two real games is `lockstep_test.py --only handover`. |
| `python tools/coop/version_test.py` | Tests that the game shows its build id at the right end of the menu bar, gives way in a narrow window, and that a package starts as a player would start it (#26). Reads the pixels of a captured frame (`versiontest/frame_shot.c`), not OCR, and that frame must show the game, not just the menu bar (#147). `--exe`, `--list`, `--only label`. Linux only, needs a build with `--assets` and a C compiler, about a minute. Logs in `local/test-*`, kept when a scenario fails. |
| `python tools/coop/view_check.py` | What each client of one session shows and hears (#30): plays one replay with local index 0 and 1 on Corneria's rails and all-range, with buttons and pokes that give the two players different numbers, and checks the camera, the HUD, the cockpit, the hit flash, the shield bar, sound and pause from a view trace (`src/port/coop/test/view_trace.h`), and that both still hash alike. `--section rails\|all-range\|both`, `--exe`, `--timeout`. It reads what a client holds to show, so the look of it stays for a picture, see `docs/coop/QA.md`. Each game starts straight in Corneria, before its intro (#148). About 1 minute, more on a busy machine. |
| `python tools/coop/input_test.py` | Input source per player (WP-14): flies Corneria's rails with a scripted gamepad through SDL and libultraship as the live local controller, while pad 0 of the replay and port 1 say something else on purpose. `live`: a live local player beside a replayed one. `alone`: no replay, a player with no stream idles. `whole`: a plain replay still flies everyone. `solo`: co-op off. `unit`: `src/port/coop/game/input.c` alone at every local index, no ROM, through the test program in `inputtest/`. Each game starts past Corneria's intro (#148). `--only a,b`, `--list`, `--exe`, `--no-build`. About 10 seconds per game, needs a build with `--assets`. Logs in `local/test-input-*`, kept when a scenario fails. |
| `python tools/coop/wingman_check.py all` | Runs how a downed wingman returns and checks it (#89): Slippy and `EVOP_RESTORE_TEAM` in Sector X (`alive`, `down`, `sitout`, under gdb) and a wingman at -1 across two level starts (`chain`). `run <scenario>` for one, `check <scenario> <folder>` on a run that exists, `--exe`, `--timeout`. Input by rule, with the team trace (`src/port/coop/test/team_trace.h`). `alive` and `down` start straight in Sector X, past its intro (#148); `sitout` and `chain` keep the map between levels. Linux only, needs gdb and a build with `--assets`, about 3 minutes, more on a busy machine. Logs in `local/test-wingman-*`. |
| `python tools/coop/steam_test.py` | Steam relay transport tests (WP-26), with no Steam and no SDK: a fake Steam in a virtual network, then the real backend on a mock library, in `steamtest/`. `--only a,b`, `--list`, `--no-build`, `--asan`. `--live host\|client --library <file>` is one side of a real run on two PCs. |
| `python tools/coop/steam_mutants.py` | The same as `net_mutants.py` for `transport_steam.c` and `steam_test.py`. |
| `python tools/coop/full_level.py` | Flies all of Corneria from level start to the map with 2 players, then proves it repeats (#142): a pilot that reads game state (`src/port/coop/test/pilot.h`) flies once and writes an ordinary replay, two plain games play it with no pilot and no debug switch, one of them drawing and one not (#147), and the replay must `PASS` and their state hashes must match on every frame, each other's and the pilot's. A third game flips one bit of player 2, which must show at exactly its frame. Prints the frames and level states reached, and each player's frames, downs and shields. `--replay <file>` skips the pilot, `--by-rule` flies by rule instead and shows why a pilot is needed, `--players`, `--frames`, `--exe`, `--timeout`. It keeps the whole path from boot and fails on a game or replay that started in a level (#148). Needs a build with `--assets`, about 3 minutes. Folders in `local/test-full-level-*` and `local/test-replay-*`. |
| `python tools/coop/test_all.py` | Every test in one command, unattended (#147): builds, then runs a serial lane for tools that bind ports, build test programs of their own or change a source file, beside `--lanes` game lanes for the rest. Full logs in `local/test-all-<stamp>/`, a summary of a few lines and one `RESULT` line. Exit code 0 when all ran and passed, 1 when one failed, 2 when all that ran passed and a step could not run: `coop-off` needs `--base-exe <file>`, the build before your change, and `builds` the other config of the same commit. `--config Release` runs it all on a Release build in `build-release`, and says what only a Debug build can do: two `fault-*` scenarios, three of `wingman_check.py` and one Steam mutant. `--only a,b`, `--skip a,b`, `--list`, `--no-build`, `--exe`, `--keep`, `--timeout`; `--game-wrap`, `--net-wrap`, `--build-wrap` on a shared machine. `python tools/coop/test_all_test.py` tests it on made-up steps: no build, no ROM, a few seconds, `check.py` runs it, folders in `local/test-testall-*`, kept when a scenario fails. |
| `python tools/coop/lockstep_test.py` | Two real games in lockstep (WP-22), each with its own folder, over loopback: input through the local input path (`src/port/coop/test/lockstep_driver.h`), and their state hash logs and input logs must be equal on every frame, and no desync report written. `sim` runs `lockstep.c` alone in a virtual network, no ROM, through the test program in `locksteptest/`, and `desync_sim` does the same for `desync.c` (WP-23, `desynctest/`). Then `steer`, `return`, `return_all_range` and `return_fox_down` (#14: a player 2-4 who goes down comes back after 150 frames for a life from the pool, at full shields; with player 0 down the return is dropped), `three`, `control`, `pause`, `save`, `zero_seed`, `slow`, `lag`, `delay`, `left`, `host_left`, `leave`, `stall`, `frozen`, `menu`, and the desync check: `desync` flips a bit on one client on rails and in all-range, and both games must name the frame, the players and the region, write a report and end the session; `desync_three` with a third game in step; `desync_control` with the check off; `handover` (#189): after a desync both folders hold both reports, byte for byte, `desync_report.py diff` works on the two in one folder, and each folder's copy of the other's log runs to its `session closed`. About 12 minutes. `--only full` flies all of Corneria with a pilot on each client and repeats it plainly, about 5 minutes; its log feeds `--only menu,release,rates,audio --feed <log>`. `--only a,b`, `--list`, `--exe`, `--release-exe`, `--no-build`, `--profiles`, `--rates`. Needs a build with `--assets`. Logs in `local/test-lockstep-*`, games in `local/test-replay-*`. |
| `python tools/coop/lockstep_mutants.py` | The same as `net_mutants.py` for `lockstep.c` and `lockstep_test.py`'s `sim`. |
| `python tools/coop/desync_report.py show\|diff` | Reads desync reports (WP-23), the `coop-desync-<frame>-player<n>.txt` a game writes into its own folder when two clients went out of step. `show <report>` prints the header and what the dump holds, and checks the dump against the region hashes. `diff <a> <b>` takes two reports of one frame, checks both dumps, names the regions that differ and the first value that does, by chunk (`gPlayer[1]`, `gActors[59]`) and byte offset, with the word at that place as hex, integer and float; `--all` lists every differing chunk. Exit 0 when it found one. No build, no ROM. |
| `python tools/coop/coop_log.py sessions\|merge` | Reads co-op logs (#172), the `coop-log-<session start>-player<n>.txt` a game writes into its own folder and receives from the other players. `sessions <folder>` lists what a folder holds; `merge <folder> [<folder> ...]` prints one timeline of every player, by time and frame (`--by frame` for the lockstep part), filtered with `--category` and `--player`, a player's clock moved with `--offset 2=-1.5`; a line two folders hold is shown once. No build, no ROM. `coop_log_test.py` checks it, from `check.py`. |
| `python tools/coop/desync_mutants.py` | The same as `net_mutants.py` for `desync.c` and `lockstep_test.py`'s `desync_sim`. |

| `python tools/coop/setup_labels.py <owner>/<repo>` | Creates the issue labels on GitHub (maintainers). |

`chaos/` is the hub's chaos relay, see its README. `nettest/` is the test program `net_test.py` drives, `sessiontest/` the one `session_test.py` drives, `locksteptest/` the one `lockstep_test.py` drives.
`cmake/coop_build_id.cmake` writes the git commit into the game for the handshake.

More test tooling (replays, state hashes, two-client harness) will live here too; see `docs/coop/QA.md` and the
roadmap.
