# Co-op tools

Python 3 scripts, so they work the same on Windows (PowerShell), Linux and macOS. Python is already needed to build
Starship. Run them from the repository root.

Building, versions and the gotchas of each OS: [docs/BUILDING.md](../../docs/BUILDING.md), "Co-op fork notes".

## Which steps for which change

`test_all.py` runs everything once per batch of PRs before a merge (CONTRIBUTING.md, #195). On a branch, run the steps
for what you changed: `python tools/coop/test_all.py --only <steps>` (`--list` prints every step with its tool). The
rows come from what each tool says it checks; when a bug gets past a row, add the step that would have caught it.
`checks` runs with every row, as `build.py` runs it anyway.

| You changed | Steps |
|---|---|
| Docs, skills, `tools/coop/` scripts | `checks`, plus the tool's own test where it has one: `package`, `replay-test` |
| `src/port/coop/net/` (transport, relay, Steam) | `net`, `net-asan`, `net-mutants`, `net-mutants-asan`, `steam`, `steam-asan`, `steam-mutants`, `join` |
| `src/port/coop/session/` (handshake, characters, logs) | `session`, `session-asan`, `session-mutants`, `session-mutants-asan`, `menu`, `menu-asan`, `join` |
| `src/port/coop/sync/` (lockstep, desync check, hash) | `lockstep`, `lockstep-full`, `lockstep-mutants`, `desync-mutants`, `hash-run-1`, `hash-run-2`, `hash-start-2`, `hash-probe-2`, `join` |
| `src/port/coop/game/` (players, hits, rules, wingmen) | `rails-2`, `rails-4`, `shots`, `effects`, `effects-allrange`, `lowhealth-rails`, `lowhealth-allrange`, `full-level`, `lockstep`, `wingman`, `coop-off` |
| The recovery: `session.c`, `lockstep_game.c`, `desync_game.c`, `desync_dump.c`, `menu.c`, the join driver | `session`, `session-asan`, `session-mutants`, `net`, `net-mutants`, `desync_dump`, `menu`, `join`, `lockstep` (its `desync`, `handover`, `stall`, `frozen`, `left`, `host_left`, `save_own` and the `survive_*` scenarios) |
| `src/port/coop/ui/` (menu, status, build id) | `menu`, `menu-asan`, `version`, `join` |
| Per-client view, camera, HUD, drawing | `views`, `view-check`, `draw`, `builds`, `rates-rails`, `rates-all-range` |
| `src/port/coop/test/`, `src/port/hooks/` | `replay-test`, `exit-test`, `hash-run-2`, `lockstep`, and the steps of every tool whose driver you touched |
| An upstream file (`src/engine/`, `src/overlays/`, `include/`, `src/port/` outside `coop/`, a `// COOP:` line) | `coop-off`, `determinism`, `hash-run-1`, `full-level`, `lockstep`, `draw`, plus the row of the area it serves; `rates-rails` and `rates-all-range` too when it touches interpolation or drawing |

The `rates-*` steps play in real time and are most of a full run (18m33s of 23m50s in Debug, docs/coop/NOTES.md,
#147), so they stay out of a branch run unless the row names them. Steps marked Linux only in `--list` are skipped
elsewhere.

A replay with checkpoints plays from where it was made. |
| `python tools/coop/player_trace.py run <replay> --players 2` | Plays a replay with several co-op players in a fresh `local/test-trace-*` folder and checks the per-frame player trace (joins on rails and in all-range with player 0, stays on player 0's path, moves). `check <trace.txt>` checks an existing trace. `rails --players 2`: input by rule on Corneria's rails, with one player and with N at the same time, and compares path progress on every frame (WP-12). `shots --players 2`: input by rule in all-range, with shots carried to the wingmen: a shot of players 1 and up must not read as an enemy's hit, and a ground hit must follow the shooter's own lasers (#86). `lowhealth --players 2`: four games one after the other, with shields held low for one player or the other, and checks the low-health radio timer against single player on every frame (#87); `--section all-range` flies there instead. About 5 minutes. `effects --players 2`: places each enemy effect of #100 on each player in turn on Corneria's rails, or after the jump with `--all-range`, and checks who it hit (`SF64_COOP_EFFECT_PROBE`). Input by rule starts straight in Corneria (#148): `rails` before the intro, the others past it. Needs the replay code from WP-03 in the build. |
| `python tools/coop/hash_check.py run\|probe\|views\|builds\|rates\|start\|draw\|base\|diff` | State hash checks (WP-04, #53). `run [<replay>]`: two runs must match and a one-bit poke must show at exactly its frame; `--players 2 --poke-player 1` for co-op. `probe`: one game checks what the hash can and cannot see, player by player and per-player array by array (#67). Without a replay they play input by rule. See `docs/coop/QA.md`. `views`: one replay with local index 0 and 1 must hash alike on Corneria's rails and all-range (#96); the client with index 1 has also ticked 6 more frames since boot (`--skew`, #129). `--level katina,fortuna` or `all` flies other Arwing levels instead, `--cvar NAME=VALUE` sets a CVar on both, and the two clients render different audio sample counts (`--audio`). `slots --level katina,fortuna,corneria`: plays a level with 1 player and with 2 and fails when co-op holds more than 15 more effects that have lived 900 frames or more (the hash log's `# ages` lines, `src/port/coop/sync/state_hash.c`) than single player, at its most, as nothing frees an effect for leaving the view in co-op (#129); a burst or a renewed set, as Fortuna's burning base or a damaged Arwing's smoke, never grows old (#284). `slots --rule-test` checks the rule on made-up samples, no game; `check.py` runs it. `builds --debug <exe> --release <exe>`: two Release runs and a Debug run of one commit must hash alike (#141). `rates`: one replay at several `gInterpolationFPS` must hash alike, with vsync off, and each run must make the draws its rate asks for, counted at the draw loop (#141). Both run in real time and draw, as no game interpolates at test speed (#137), and each game must log its draws. `draw`: one replay with and without `SF64_COOP_TEST_NO_DRAW` must hash alike on Corneria's rails and all-range, from each start or the one `--start` names, with 0 draws in one and more in the other (#147). `base --base <exe>`: input by rule through the menus with co-op off must hash alike on this build and the one before a change; `--level <name>` starts both in that level instead, through its intro (Macbeth, Sector Y and the rest, #283), and `--frames` sets how long. `start`: a game from the menus and two started in the level from its seeds must hash alike (#148). `run`, `probe` and `views` play straight in Corneria, `builds` and `rates` through the menus. Every subcommand but `diff`, run by hand, deletes the folders it made under `local/` when it passes, those of the games it started too, and keeps them when it fails (#308, #315); `--keep-folders` keeps them after a pass too, as for reading the pilot's folder that `views --pilot` prints. Under a run that notes them (`test_all.py`, `replay_test.py`) it leaves them to that run. |
| `python tools/coop/determinism.py [<replay>]` | Determinism check (WP-02): plays one replay alone as the baseline, then again several times at once under conditions that can differ between machines (graphics backend, window size, audio timing, FMA3), and each run's state hash must equal the baseline on every frame. Every run is in real time but the variants `speed`, no frame limit with drawing (#137), and `no-draw`, which runs as the other tools do (#147). A run that did not make the draws its variant asks for fails. Without a replay it plays input by rule, Corneria's rails into all-range. It keeps the whole path from boot and fails on a game that started in a level (#148). `--only a,b`, `--exe`, `--timeout`. |
| `python tools/coop/replay_test.py` | Tests the replay tools themselves (#54): records a short replay nobody plays, then plays it whole and damaged through `replay.py`, `hash_check.py` and `determinism.py`. Only the whole file may pass, and a decoy `SHIP_HOME` must stay untouched. Each tool's games must log the right speed, and on Linux a tool started from a shell without SDL drivers must give its game the silent ones, read from the running game's environment, and `hash_check.py rates` must hold at real time and fail at speed (#137). A replay made in a level plays from there, and `determinism.py` and `full_level.py` refuse it (#148). `person` (a recording for a person to play, real time) stops its game with SIGTERM once it draws (`imgui.ini`), not as soon as its config is there, which comes before the game's stop handler is in; a game still running 15 s after the signal gets SIGKILL and fails it, and a tool still running 600 s after it started fails its scenario and is stopped with every process it started (#308). `--only a,b`, `--list`, `--exe <file>`, `--jobs <n>` (scenarios at a time). About 2 minutes, more on a busy machine, needs a build with `--assets`. Logs in `local/test-replaytools-*`; when every scenario holds it deletes them and every folder the tools it started made (`OwnedFolders` in `run_folder.py`), those of the tools that fail on purpose too (#308), and keeps them all when one fails. `python tools/coop/replay_test_test.py` tests the waits of `person` and the tool's limit with a stand-in for the game (a late stop handler, one that never comes, a tool that does not end): Linux, no build, no ROM, about 12 s, `check.py` runs it. |
| `python tools/coop/exit_test.py` | Tests that a test run ends soon after SIGTERM, SIGINT or SIGQUIT (#71) or a crash (#98): without a replay, recording and playing. Each game must end within 10 s, with exit code 0 after a stop signal and 1 after a crash, and the report, the replay and the hash log must keep their end; a crash must also leave a crash report. `crash-*` send a crash signal, `fault-*` use gdb for a real fault on the main or the audio thread and for a crash handler that hangs. libultraship's crash handler can stop on malloc's lock when the signal lands inside malloc or free (#158): then the alarm of `stop_signal.c` ends the test output and writes the crash report 5 s after the crash, and the run's line says `report by the alarm`. `crash-*` take either; `fault-main` and `fault-audio` must end by libultraship's handler, `fault-stuck` by the alarm. After a crash the report may be one frame ahead of the hash log (two listeners), never behind. `plain` and `crash-plain` show that a game with no test variable keeps upstream's handlers. Every game draws, and a run that logged no draws fails (#147). `--only a,b`, `--skip a,b`, `--repeat n` (default 3), `--jobs n` (games at a time, default 1: each game has a folder of its own and most of its 6 to 16 s is waiting on the clock; the 48 games took 376 s one at a time, 103 s with 4, 56 s with 8, and the `exit-test` step of `test_all.py` takes 4, #290), `--exe`, `--list`.
