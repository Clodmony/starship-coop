# Co-op tools

Python 3 scripts, so they work the same on Windows (PowerShell), Linux and macOS. Python is already needed to build
Starship. Run them from the repository root.

| Script | What it does |
|---|---|
| `python tools/coop/build.py` | Configure, build and run the checks; prints `build: OK` or `build: FAILED at <step>`. `--quiet` for a summary only, `--config Release`, `--assets` (needs `baserom.z64`), `--clean`. CI runs the same script. |
| `python tools/coop/net_test.py` | Transport tests: a virtual network, then two real processes through the chaos relay. `--only a,b`, `--list`, `--no-build`, `--asan` (the same under AddressSanitizer and UBSan, not on Windows). Needs a configured build directory, no ROM. Logs in `local/test-net/`. |
| `python tools/coop/session_test.py` | Session tests: the handshake (WP-21) with build, ROM, CVar and platform mismatches, and characters (WP-34) with three clients, in a virtual network, then real processes over UDP and the chaos relay. `--only a,b`, `--list`, `--no-build`, `--asan` (the same under AddressSanitizer and UBSan, not on Windows; CI runs it on Linux). No ROM needed. Logs in `local/test-session/`. |
| `python tools/coop/replay.py record\|play <file>` | Records or plays back controller input (WP-03) in a fresh `local/test-replay-*` folder with its own `SHIP_HOME`. `record` stops when you close the window, or by itself with `--frames <n>`. `play` runs unattended and exits 0 on `PASS`: only a whole file can pass. `--hash-log` also writes the per-frame state hash, `--exe`, `--timeout`. A file only plays on the build and platform it was recorded on. |
| `python tools/coop/player_trace.py run <replay> --players 2` | Plays a replay with several co-op players in a fresh `local/test-trace-*` folder and checks the per-frame player trace (joins on rails and in all-range with player 0, stays on player 0's path, moves). `check <trace.txt>` checks an existing trace. `rails --players 2`: input by rule on Corneria's rails, with one player and with N at the same time, and compares path progress on every frame (WP-12). Needs the replay code from WP-03 in the build. |
| `python tools/coop/hash_check.py run\|probe\|diff` | State hash checks (WP-04, #53). `run [<replay>]`: two runs must match and a one-bit poke must show at exactly its frame; `--players 2 --poke-player 1` for co-op. `probe`: one game checks what the hash can and cannot see, player by player and per-player array by array (#67). Without a replay they play input by rule. See `docs/coop/QA.md`. |
| `python tools/coop/determinism.py <replay>` | Determinism check (WP-02): plays one replay alone as the baseline, then again several times at once under conditions that can differ between machines (graphics backend, window size, audio timing, FMA3), and each run's state hash must equal the baseline on every frame. `--only a,b`, `--exe`, `--timeout`. |
| `python tools/coop/replay_test.py` | Tests the replay tools themselves (#54): records a short replay nobody plays, then plays it whole and damaged through `replay.py`, `hash_check.py` and `determinism.py`. Only the whole file may pass, and a decoy `SHIP_HOME` must stay untouched. `--only a,b`, `--list`, `--exe <file>`, `--jobs <n>` (scenarios at a time). About 5 minutes, needs a build with `--assets`. Logs in `local/test-replaytools-*`, kept when a scenario fails. |
| `python tools/coop/exit_test.py` | Tests that a test run stops soon after SIGTERM, SIGINT or SIGQUIT (#71): without a replay, recording and playing. Each game must end within 10 s with exit code 0, and the report, the replay and the hash log must keep their end. `plain` shows that a game with no test variable keeps upstream's handler. `--only a,b`, `--repeat n` (default 3), `--exe`, `--list`. Linux only, about 7 s per game, needs a build with `--assets`. Logs in `local/test-*`, kept when a run fails. |
| `python tools/coop/net_mutants.py` | Mutation check for the transport: breaks one behaviour of `net_core.c` at a time, rebuilds, and requires the named `net_test.py` scenarios to fail. Prints caught or SURVIVED per break; exit 0 only when all are caught. `--only a,b`, `--list`, `--check` (patterns only, no build). About 10 minutes. Run it after changing `net_core.c`, and add a break for every bug you fix there. |
| `python tools/coop/session_mutants.py` | The same for the session: breaks one behaviour of `session.c` at a time and requires the named `session_test.py` scenarios to fail. Same options as `net_mutants.py`, plus `--asan` for the breaks only the sanitizers can see. The top of the file lists the changes no test can see, with the reason. About three minutes. Run it after changing `session.c`, and add a break for every bug you fix there. Both tools run on `mutants.py`, which also holds the rules for how a run guards the source. |
| `python tools/coop/check.py` | Repository checks, also run by CI: no ROMs or asset archives tracked, no file over 5 MB, skills mirrored, unique protocol ids, every break in `net_mutants.py` and `session_mutants.py` still matches. Prints `ALL OK`. |
| `python tools/coop/new_worktree.py <issue> <slug>` | Worktree plus branch `issue/<issue>-<slug>` from `origin/coop`, with submodules. |
| `python tools/coop/sp_audit.py` | Single-player assumptions audit (WP-05): every `gPlayer[0]`, `gPlayer->`, `gMainController` and `gCamCount` site in the game code with its function and the verdict from `docs/coop/audit/sp-verdicts.tsv`; writes `docs/coop/audit/single-player.md`. `--check` fails when the list is stale, a site has no verdict or a site is new, `--todo` lists functions without a verdict. A site the committed list does not have stops the rerun and stays red, named with the row it would take its verdict from, until `--accept` takes it in: read those sites, fix the rows that do not fit, then run that one command, also after an upstream sync. A file git does not track gets a warning. `python tools/coop/sp_audit_test.py` tests the tool itself (`--only a,b`, `--list`): no build, no ROM, a few seconds, folders in `local/test-spaudit-*`, kept when a scenario fails. |
| `python tools/coop/join_test.py` | Real game clients through the join flow (WP-24): host and clients over loopback, nobody at the keyboard, each with its own replay and seeds. Compares the state hash logs frame by frame from the level start, and the seeds, team values and characters each game ended up with. `--only a,b`, `--list`, `--frames <n>`. Needs a build with assets; folders in `local/test-join-*` and `local/test-replay-*`. The scripted flow in the game is `src/port/coop/test/join_driver.h`. |
| `python tools/coop/menu_test.py` | Co-op menu tests (WP-25): `sim` runs the menu layer on the real session in a virtual network and checks what can be chosen, status and ping, `udp` does a shorter run over real sockets. `--game` also starts real games with no window and clicks the real ImGui widgets: `game` for host, join, a taken character, ping, a refusal, `game_level` for the Start button into a level, with the state hash logs compared as in `join_test.py`, `game_level_map` the same for a host that came from the map. `--only a,b`, `--list`, `--no-build`, `--exe`, `--asan` (`sim` and `udp` under AddressSanitizer and UBSan, not on Windows), `--keep`. `sim` and `udp` need no ROM, `--game` needs a build with assets. Logs in `local/test-menu/`. |
| `python tools/coop/sync_skills.py` | Copies `.agents/skills` to `.claude/skills`. Edit skills in `.agents/skills` only. |
| `python tools/coop/setup_labels.py <owner>/<repo>` | Creates the issue labels on GitHub (maintainers). |

`chaos/` is the hub's chaos relay, see its README. `nettest/` is the test program `net_test.py` drives, `sessiontest/` the one `session_test.py` drives, `menutest/` the one `menu_test.py` drives.
`cmake/coop_build_id.cmake` writes the git commit into the game for the handshake.

More test tooling (replays, state hashes, two-client harness) will live here too; see `docs/coop/QA.md` and the
roadmap.
