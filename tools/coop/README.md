# Co-op tools

Python 3 scripts, so they work the same on Windows (PowerShell), Linux and macOS. Python is already needed to build
Starship. Run them from the repository root.

| Script | What it does |
|---|---|
| `python tools/coop/build.py` | Configure, build and run the checks; prints `build: OK` or `build: FAILED at <step>`. `--quiet` for a summary only, `--config Release`, `--assets` (needs `baserom.z64`), `--clean`. CI runs the same script. |
| `python tools/coop/net_test.py` | Transport tests: a virtual network, then two real processes through the chaos relay. `--only a,b`, `--list`, `--no-build`, `--asan` (the same under AddressSanitizer and UBSan, not on Windows). Needs a configured build directory, no ROM. Logs in `local/test-net/`. |
| `python tools/coop/session_test.py` | Session tests: the handshake (WP-21) with build, ROM, CVar and platform mismatches, and characters (WP-34) with three clients, in a virtual network, then real processes over UDP and the chaos relay. `--only a,b`, `--list`, `--no-build`, `--asan` (the same under AddressSanitizer and UBSan, not on Windows; CI runs it on Linux). No ROM needed. Logs in `local/test-session/`. |
| `python tools/coop/replay.py record\|play <file>` | Records or plays back controller input (WP-03) in a fresh `local/test-replay-*` folder with its own `SHIP_HOME`. `record` stops when you close the window, or by itself with `--frames <n>`. `play` runs unattended and exits 0 on `PASS`: only a whole file can pass. `--hash-log` also writes the per-frame state hash, `--exe`, `--timeout`. A file only plays on the build and platform it was recorded on. A test game runs with no frame limit, makes no sound and on Linux opens no window (`game_env`, #137); `--speed 1` gives real time, and a driver set in the shell still wins. `record` without `--frames` stays as a person needs it. |
| `python tools/coop/player_trace.py run <replay> --players 2` | Plays a replay with several co-op players in a fresh `local/test-trace-*` folder and checks the per-frame player trace (joins on rails and in all-range with player 0, stays on player 0's path, moves). `check <trace.txt>` checks an existing trace. `rails --players 2`: input by rule on Corneria's rails, with one player and with N at the same time, and compares path progress on every frame (WP-12). `shots --players 2`: input by rule in all-range, with shots carried to the wingmen: a shot of players 1 and up must not read as an enemy's hit, and a ground hit must follow the shooter's own lasers (#86). `lowhealth --players 2`: four games one after the other, with shields held low for one player or the other, and checks the low-health radio timer against single player on every frame (#87); `--section all-range` flies there instead. About 5 minutes. `effects --players 2`: places each enemy effect of #100 on each player in turn on Corneria's rails, or after the jump with `--all-range`, and checks who it hit (`SF64_COOP_EFFECT_PROBE`). Needs the replay code from WP-03 in the build. |
| `python tools/coop/hash_check.py run\|probe\|views\|builds\|rates\|diff` | State hash checks (WP-04, #53). `run [<replay>]`: two runs must match and a one-bit poke must show at exactly its frame; `--players 2 --poke-player 1` for co-op. `probe`: one game checks what the hash can and cannot see, player by player and per-player array by array (#67). Without a replay they play input by rule. See `docs/coop/QA.md`. `views`: one replay with local index 0 and 1 must hash alike on Corneria's rails and all-range (#96). `builds --debug <exe> --release <exe>`: two Release runs and a Debug run of one commit must hash alike (#141). `rates`: one replay at several `gInterpolationFPS` must hash alike, with vsync off, and each run must make the draws its rate asks for, counted at the draw loop (#141). Both run in real time, as no game interpolates at test speed (#137). |
| `python tools/coop/hash_check.py run\|probe\|diff` | State hash checks (WP-04, #53). `run [<replay>]`: two runs must match and a one-bit poke must show at exactly its frame; `--players 2 --poke-player 1` for co-op. `probe`: one game checks what the hash can and cannot see, player by player and per-player array by array (#67). Without a replay they play input by rule. See `docs/coop/QA.md`. |
| `python tools/coop/determinism.py [<replay>]` | Determinism check (WP-02): plays one replay alone as the baseline, then again several times at once under conditions that can differ between machines (graphics backend, window size, audio timing, FMA3), and each run's state hash must equal the baseline on every frame. Every run is in real time but the variant `speed`, which runs as the other tools do (#137). Without a replay it plays input by rule, Corneria's rails into all-range. `--only a,b`, `--exe`, `--timeout`. |
| `python tools/coop/replay_test.py` | Tests the replay tools themselves (#54): records a short replay nobody plays, then plays it whole and damaged through `replay.py`, `hash_check.py` and `determinism.py`. Only the whole file may pass, and a decoy `SHIP_HOME` must stay untouched. Each tool's games must log the right speed, and on Linux a tool started from a shell without SDL drivers must give its game the silent ones, read from the running game's environment, and `hash_check.py rates` must hold at real time and fail at speed (#137). `--only a,b`, `--list`, `--exe <file>`, `--jobs <n>` (scenarios at a time). About 2 minutes, more on a busy machine, needs a build with `--assets`. Logs in `local/test-replaytools-*`, kept when a scenario fails. |
| `python tools/coop/exit_test.py` | Tests that a test run ends soon after SIGTERM, SIGINT or SIGQUIT (#71) or a crash (#98): without a replay, recording and playing. Each game must end within 10 s, with exit code 0 after a stop signal and 1 after a crash, and the report, the replay and the hash log must keep their end; a crash must also leave its crash log. `crash-*` send a crash signal, `fault-*` use gdb for a real fault on the main or the audio thread and for a crash handler that hangs. `plain` and `crash-plain` show that a game with no test variable keeps upstream's handlers. `--only a,b`, `--repeat n` (default 3), `--exe`, `--list`. Linux only, about 7 s per game, needs a build with `--assets`, and gdb for `fault-*`. Logs in `local/test-*`, kept when a run fails. |
| `python tools/coop/net_mutants.py` | Mutation check for the transport: breaks one behaviour of `net_core.c` at a time, rebuilds, and requires the named `net_test.py` scenarios to fail. Prints caught or SURVIVED per break; exit 0 only when all are caught. `--only a,b`, `--list`, `--check` (patterns only, no build), `--asan` (the breaks only the sanitizers can see, not on Windows). About 10 minutes. Run it after changing `net_core.c`, and add a break for every bug you fix there. |
| `python tools/coop/session_mutants.py` | The same for the session: breaks one behaviour of `session.c` at a time and requires the named `session_test.py` scenarios to fail. Same options as `net_mutants.py`. The top of the file lists the changes no test can see, with the reason. About three minutes. Run it after changing `session.c`, and add a break for every bug you fix there. Both tools run on `mutants.py`, which also holds the rules for how a run guards the source. |
| `python tools/coop/check.py` | Repository checks, also run by CI: no ROMs, asset archives or Steamworks SDK files tracked, no file over 5 MB, skills mirrored, unique protocol ids, every break in `net_mutants.py` and `session_mutants.py` still matches, `script_reader_test.py` passes, every test tool gets a run folder of its own (`run_folder_test.py`), `sp_audit.py --check` and `sp_audit_test.py` pass. Runs inside `build.py`, so a stale audit fails a local build too. Prints `ALL OK`. |
| `python tools/coop/new_worktree.py <issue> <slug>` | Worktree plus branch `issue/<issue>-<slug>` from `origin/coop`, with submodules. |
| `python tools/coop/sp_audit.py` | Single-player assumptions audit (WP-05): every `gPlayer[0]`, `gPlayer->`, bare `gPlayer` argument, `gMainController` and `gCamCount` site, and every write and test of who fired (`dmgSource`, `sourceId`, #86), in the game code with its function and the verdict from `docs/coop/audit/sp-verdicts.tsv`; writes `docs/coop/audit/single-player.md`. `--check` compares the list with what a rerun would write, in everything but line numbers: it fails when a site is new, lost, has another verdict, basis or note, or has no verdict, or when any other text differs. A moved line passes until the next rerun refreshes its number. `--todo` lists functions without a verdict. A site the committed list does not have stops the rerun and stays red, named with the row it would take its verdict from, until `--accept` takes it in: read those sites, fix the rows that do not fit, then run that one command, also after an upstream sync. Anything but a new site needs only the plain rerun. A file git does not track gets a warning, and so does a tracked file that is deleted but not committed. `python tools/coop/sp_audit_test.py` tests the tool itself (`--only a,b`, `--list`): no build, no ROM, a few seconds, folders in `local/test-spaudit-*`, kept when a scenario fails. |
| `python tools/coop/script_reader.py CO S59:34` | Prints a level event script from your own `sf64.o2r` (#90), the command marked with `>`; `Corneria 17.8` is the same kind of reference. A level alone lists its scripts, no argument the levels. `--o2r <file>`, by default the first of `build-cmake/`, `build/x64/` and the repo root. It reads that one file and writes nothing; what it prints is game data, so keep it out of git, issues and PRs. `python tools/coop/script_reader_test.py` tests the tool on made-up scripts (`--only a,b`, `--list`): no build, no ROM, a few seconds, `check.py` runs it, folders in `local/test-scriptreader-*`, kept when a scenario fails. |
| `python tools/coop/run_folder_test.py` | Tests that a test tool's run gets a folder of its own, however close together runs start (#104): `replay.py`, `player_trace.py`, `exit_test.py`, `net_test.py`, `session_test.py` and `mutants.py` as real processes with the clock stopped, and `make_run_folder` in `run_folder.py`, which they all share, across processes and threads. `--out` must stay a folder runs can share. `--only a,b`, `--list`. No build, no ROM, a few seconds; `check.py` runs it. Folders in `local/test-runfolder-*`, kept when a scenario fails. |
| `python tools/coop/join_test.py` | Real game clients through the join flow (WP-24): host and clients over loopback, nobody at the keyboard, each with its own replay and seeds. Compares the state hash logs frame by frame from the level start, and the seeds, team values and characters each game ended up with. `--only a,b`, `--list`, `--frames <n>`. Needs a build with assets; folders in `local/test-join-*` and `local/test-replay-*`. The scripted flow in the game is `src/port/coop/test/join_driver.h`. |
| `python tools/coop/menu_test.py` | Co-op menu tests (WP-25): `sim` runs the menu layer on the real session in a virtual network and checks what can be chosen, status and ping, `udp` does a shorter run over real sockets. `--game` also starts real games with no window and clicks the real ImGui widgets: `game` for host, join, a taken character, ping, a refusal, `game_level` for the Start button into a level, with the state hash logs compared as in `join_test.py`, `game_level_map` the same for a host that came from the map. `--only a,b`, `--list`, `--no-build`, `--exe`, `--asan` (`sim` and `udp` under AddressSanitizer and UBSan, not on Windows), `--keep`. `sim` and `udp` need no ROM, `--game` needs a build with assets. Logs in `local/test-menu/`. |
| `python tools/coop/package.py --config Release` | Puts a built game into `<build dir>/package/starship-coop-<id>-<os>-x64/` for CI to upload (#26). `<id>` comes from `coop/coop_build_id.h` in the build folder. Only listed files go in, plus `starship.o2r`, which it packs itself from the 13 tracked `port/` files, with no Torch build. The result is scanned for ROMs and asset archives by name, by first bytes and for a ROM header inside a file; `starship.o2r` must equal, byte for byte, what the tracked files give. `--out <folder>`, and `--scan <folder>` only scans, for example a downloaded artifact. `python tools/coop/package_test.py` tests it: no build, no ROM, a few seconds, run it after changing `package.py`. |
| `python tools/coop/version_test.py` | Tests that the game shows its build id at the right end of the menu bar, gives way in a narrow window, and that a package starts as a player would start it (#26). Reads the pixels of a captured frame (`versiontest/frame_shot.c`), not OCR. `--exe`, `--list`. Linux only, needs a build with `--assets` and a C compiler, about a minute. Logs in `local/test-*`, kept when a scenario fails. |
| `python tools/coop/view_check.py` | What each client of one session shows and hears (#30): plays one replay with local index 0 and 1 on Corneria's rails and all-range, with buttons and pokes that give the two players different numbers, and checks the camera, the HUD, the cockpit, the hit flash, the shield bar, sound and pause from a view trace (`src/port/coop/test/view_trace.h`), and that both still hash alike. `--section rails\|all-range\|both`, `--exe`, `--timeout`. It reads what a client holds to show, so the look of it stays for a picture, see `docs/coop/QA.md`. About 2 minutes, more on a busy machine. |
| `python tools/coop/input_test.py` | Input source per player (WP-14): flies Corneria's rails with a scripted gamepad through SDL and libultraship as the live local controller, while pad 0 of the replay and port 1 say something else on purpose. `live`: a live local player beside a replayed one. `alone`: no replay, a player with no stream idles. `whole`: a plain replay still flies everyone. `solo`: co-op off. `unit`: `src/port/coop/game/input.c` alone at every local index, no ROM, through the test program in `inputtest/`. `--only a,b`, `--list`, `--exe`, `--no-build`. About a minute per game, needs a build with `--assets`. Logs in `local/test-input-*`, kept when a scenario fails. |
| `python tools/coop/wingman_check.py all` | Runs how a downed wingman returns and checks it (#89): Slippy and `EVOP_RESTORE_TEAM` in Sector X (`alive`, `down`, `sitout`, under gdb) and a wingman at -1 across two level starts (`chain`). `run <scenario>` for one, `check <scenario> <folder>` on a run that exists, `--exe`, `--timeout`. Input by rule, with the team trace (`src/port/coop/test/team_trace.h`). Linux only, needs gdb and a build with `--assets`, about 3 minutes, more on a busy machine. Logs in `local/test-wingman-*`. |
| `python tools/coop/steam_test.py` | Steam relay transport tests (WP-26), with no Steam and no SDK: a fake Steam in a virtual network, then the real backend on a mock library, in `steamtest/`. `--only a,b`, `--list`, `--no-build`, `--asan`. `--live host\|client --library <file>` is one side of a real run on two PCs. |
| `python tools/coop/steam_mutants.py` | The same as `net_mutants.py` for `transport_steam.c` and `steam_test.py`. |
| `python tools/coop/full_level.py` | Flies all of Corneria from level start to the map with 2 players, then proves it repeats (#142): a pilot that reads game state (`src/port/coop/test/pilot.h`) flies once and writes an ordinary replay, two plain games play it with no pilot and no debug switch, and the replay must `PASS` and their state hashes must match on every frame, each other's and the pilot's. A third game flips one bit of player 2, which must show at exactly its frame. Prints the frames and level states reached, and each player's frames, downs and shields. `--replay <file>` skips the pilot, `--by-rule` flies by rule instead and shows why a pilot is needed, `--players`, `--frames`, `--exe`, `--timeout`. Needs a build with `--assets`, about 3 minutes. Folders in `local/test-full-level-*` and `local/test-replay-*`. |
| `python tools/coop/sync_skills.py` | Copies `.agents/skills` to `.claude/skills`. Edit skills in `.agents/skills` only. |
| `python tools/coop/setup_labels.py <owner>/<repo>` | Creates the issue labels on GitHub (maintainers). |

`chaos/` is the hub's chaos relay, see its README. `nettest/` is the test program `net_test.py` drives, `sessiontest/` the one `session_test.py` drives.
`cmake/coop_build_id.cmake` writes the git commit into the game for the handshake.

More test tooling (replays, state hashes, two-client harness) will live here too; see `docs/coop/QA.md` and the
roadmap.
