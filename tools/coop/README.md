# Co-op tools

Python 3 scripts, so they work the same on Windows (PowerShell), Linux and macOS. Python is already needed to build
Starship. Run them from the repository root.

Building, versions and the gotchas of each OS: [docs/BUILDING.md](../../docs/BUILDING.md), "Co-op fork notes".

## Which steps for which change

`test_all.py` runs everything once per batch of PRs before a merge (CONTRIBUTING.md, #195). On a branch, run the steps
for what you changed: `python tools/coop/test_all.py --only <steps>` (`--list` prints every step with its tool). The
rows come from what each tool says it checks; when a bug gets past a row, add the step that would have caught it.
`checks` runs with every row, as `build.py` runs it anyway.

| You changed | Steps |
|---|---|
| Docs, skills, `tools/coop/` scripts | `checks`, plus the tool's own test where it has one: `package`, `replay-test` |
| `src/port/coop/net/` (transport, relay, Steam) | `net`, `net-asan`, `net-mutants`, `net-mutants-asan`, `steam`, `steam-asan`, `steam-mutants`, `join` |
| `src/port/coop/session/` (handshake, characters, logs) | `session`, `session-asan`, `session-mutants`, `session-mutants-asan`, `menu`, `menu-asan`, `join` |
| `src/port/coop/sync/` (lockstep, desync check, hash) | `lockstep`, `lockstep-full`, `lockstep-mutants`, `desync-mutants`, `hash-run-1`, `hash-run-2`, `hash-start-2`, `hash-probe-2`, `join` |
| `src/port/coop/game/` (players, hits, rules, wingmen) | `rails-2`, `rails-4`, `shots`, `effects`, `effects-allrange`, `lowhealth-rails`, `lowhealth-allrange`, `full-level`, `lockstep`, `wingman`, `coop-off` |
| The recovery: `session.c`, `lockstep_game.c`, `desync_game.c`, `desync_dump.c`, `menu.c`, the join driver | `session`, `session-asan`, `session-mutants`, `net`, `net-mutants`, `desync_dump`, `menu`, `join`, `lockstep` (its `desync`, `handover`, `stall`, `frozen`, `left`, `host_left`, `save_own` and the `survive_*` scenarios) |
| `src/port/coop/ui/` (menu, status, build id) | `menu`, `menu-asan`, `version`, `join` |
| Per-client view, camera, HUD, drawing | `views`, `view-check`, `draw`, `builds`, `rates-rails`, `rates-all-range` |
| `src/port/coop/test/`, `src/port/hooks/` | `replay-test`, `exit-test`, `hash-run-2`, `lockstep`, and the steps of every tool whose driver you touched |
| An upstream file (`src/engine/`, `src/overlays/`, `include/`, `src/port/` outside `coop/`, a `// COOP:` line) | `coop-off`, `determinism`, `hash-run-1`, `full-level`, `lockstep`, `draw`, plus the row of the area it serves; `rates-rails` and `rates-all-range` too when it touches interpolation or drawing |

The `rates-*` steps play in real time and are most of a full run (18m33s of 23m50s in Debug, docs/coop/NOTES.md,
#147), so they stay out of a branch run unless the row names them. Steps marked Linux only in `--list` are skipped
elsewhere.

| `python tools/coop/replay.py record\|play <file>` | Records or plays back controller input (WP-03) in a fresh `local/test-replay-*` folder with its own `SHIP_HOME`. `record` stops when you close the window, or by itself with `--frames <n>`. `play` runs unattended and exits 0 on `PASS`: only a whole file can pass. `--hash-log` also writes the per-frame state hash, `--cvar NAME[=VALUE]` (repeatable) puts a CVar into the run folder's config, so a base build plays with the same ones (#121), `--exe`, `--timeout`. A test game runs with no frame limit, makes no sound, on Linux opens no window (`game_env`, #137) and does not draw (#147): its draw code runs, and the renderer gets an empty display list. `--speed 1` gives real time, `--speed` also gives drawing, and a driver set in the shell still wins. `record` without `--frames` stays as a person needs it. `--start level` or `flying` starts a game straight in Corneria, before or past its intro (#148): the table in `docs/coop/QA.md` says which tool plays which. Input by rule starts straight in Corneria (#148): `rails` before the intro, the others past it. Needs the replay code from WP-03 in the build. |
| `python tools/coop/hash_check.py run\|probe\|views\|builds\|rates\|start\|draw\|base\|diff` | State hash checks (WP-04, #53). `run [<replay>]`: two runs must match and a one-bit poke must show at exactly its frame; `--players 2 --poke-player 1` for co-op. `probe`: one game checks what the hash can and cannot see, player by player and per-player array by array (#67). Both run in real time and draw, as no game interpolates at test speed (#137), and each game must log its draws. `draw`: one replay with and without `SF64_COOP_TEST_NO_DRAW` must hash alike on Corneria's rails and all-range, from each start or the one `--start` names, with 0 draws in one and more in the other (#147). `base --base <exe>`: input by rule through the menus with co-op off must hash alike on this build and the one before a change. `start`: a game from the menus and two started in the level from its seeds must hash alike (#148). `run`, `probe` and `views` play straight in Corneria, `builds` and `rates` through the menus. |
| `python tools/coop/determinism.py [<replay>]` | Determinism check (WP-02): plays one replay alone as the baseline, then again several times at once under conditions that can differ between machines (graphics backend, window size, audio timing, FMA3), and each run's state hash must equal the baseline on every frame. Each tool's games must log the right speed, and on Linux a tool started from a shell without SDL drivers must give its game the silent ones, read from the running game's environment, and `hash_check.py rates` must hold at real time and fail at speed (#137). Every game must draw or not draw as its tool says, and the tools that need pixels must fail when they get none (`*-no-draw`, #147).
